Genie guide

1. The Genie flavours

For business users

Flavour What it is
Genie Agents (formerly Genie Spaces) A curated, domain-specific chat over a set of tables and metric views that you configure: users ask questions, Genie writes the SQL and returns results and charts
Genie One (formerly Databricks One) The simplified UI for business users, one entry point for dashboards, Genie Agents and apps, plus workspace-wide questions that Genie routes to the right data
Ask Genie on dashboards An Ask Genie button on a published AI/BI dashboard, backed by a Genie Agent over the dashboard's datasets
Genie in Microsoft Teams Ask Genie from a Teams DM, channel or group chat (@Databricks Genie), answered by Genie One or by a Genie Agent pinned to the chat; also works from Microsoft 365 Copilot
Genie in Slack Ask Genie from a Slack DM, channel or group DM (@Genie), answered by Genie One or by a Genie Agent pinned to the channel

"Genie One is the simplified Azure Databricks UI for business users, a single entry point for interacting with data and AI without navigating technical concepts like compute, queries, models, or notebooks." (Genie One)

For developers and agents

Flavour What it is
Genie Code The AI coding and data assistant for engineers in the workspace (notebooks, SQL editor, pipelines)
Conversation API REST API to ask a specific Genie Agent questions from your own apps and chatbots
Genie Agent MCP server Managed MCP server that lets an AI agent query one Genie Agent in natural language
Genie One MCP server Managed MCP server (system.ai.genie_one_mcp) that exposes Genie One, workspace-wide, to MCP clients such as Claude or Cursor
Genie One API HTTP API to ask Genie One questions from your own backend and stream the answers

How to choose: use a Genie Agent for each domain that needs curated, accurate answers (for example UA performance or finance). Put those agents in front of business users through Genie One, Teams or Slack. Use the Conversation API or Genie Agent MCP when your own tools or AI agents need answers from a specific agent. Use Genie One MCP when an agent should search across everything the user can access.

2. The semantic layer behind Genie and Genie Ontology

Genie answers from the business context you give it. In Azure Databricks that context is Unity Catalog semantics:

"Unity Catalog semantics is a collection of tools to help you define standard business metrics, terms, and organizational structures on top of your catalog data." (Unity Catalog semantics)

Together these components form the modeled knowledge in the Genie Ontology. Genie One and Genie Code also learn context automatically from your dashboards, queries and Genie Agents. When the two conflict, what you model wins:

"Genie treats modeled knowledge as more authoritative than learned knowledge, so it takes precedence when the two conflict." (Genie Ontology)

2a. Metric views

Governed, reusable definitions of your KPIs (ROAS, CAC, LTV, rebill rate), defined once and used by Genie, dashboards and Tableau alike. Genie Agents can use metric views directly as data sources (Metric views).

"Metric views are particularly effective for Genie Agents because they pre-define metrics, dimensions, and aggregations." (Best practices)

2b. Domains

A business-aligned grouping of data assets (for example UA/Marketing, Finance, Product, Payments, HR), shown on the Discover page. Domains are built on governed tags, which you already use for ABAC.

"To add an asset to a domain, add the corresponding governed tag to the asset." (Domains)

Tagging a catalog or schema puts everything in it into the domain. Domains can be managed as code with the Terraform databricks_domain resource.

2c. Pages

Pages are in Beta. A Page is a governed definition of one business term, owned and published within a domain.

"A Page is a governed, authoritative definition of a business concept, such as a critical term, entity, or acronym." (Pages)

Genie One uses the Page's definition and cites the Page in its answer. Good candidates for you are terms like pLTV, rebill, trial conversion or "UA cohort". Page content is stored at account level and may be replicated globally, so keep PII and sensitive data out of Pages.

2d. Wikis

Wikis are in Beta. A wiki documents one table: what it means, how to use it, known caveats. A Page defines a concept that spans many assets.

"A wiki lets your team document a table's meaning, intended use, and sources, then collaborate on that information." (Wikis)

A good fit for the gold tables behind the UA report and the subscription One Big Table.

2e. Synonyms

Synonyms let users ask in their own words. You can set them in three places:

  • Metric views: synonyms on fields and measures (YAML 1.1, up to 10 each), for example ['revenue', 'total sales'].

    "Alternative names for AI and BI tools to discover the field." (Metric view YAML reference)

  • Pages: each Page has a synonyms field for alternative names of the concept (Pages).

  • Genie Agents: column synonyms that apply to one agent only.

    "This metadata is scoped to your Genie Agent and does not overwrite metadata stored in Unity Catalog." (Best practices)

Put shared synonyms in the metric views, so every agent and tool gets them.

2f. Certification and deprecation

A system tag (system.certification_status) that marks assets as certified or deprecated. It applies to catalogs, schemas, tables, views, dashboards, Genie Agents and more.

"This helps Genie One improve its answers by prioritizing the assets your organization vouches for." (Certify or deprecate data)

Certify the gold tables and metric views your contracts cover, and deprecate legacy tables so Genie stops using them.

3. Best practices for Genie Agents

Keep each agent focused

"Stay focused: Include only the tables necessary to answer the questions you want the agent to handle. Aim for five or fewer tables." (Best practices)

"An agent should answer questions for a particular topic and audience, not general questions across various domains." (same page)

Invest in metadata first

"Quality table and column descriptions in Unity Catalog are critical for Genie accuracy." (Best practices)

Define primary and foreign keys in Unity Catalog too; Genie uses them when it writes SQL (Concepts).

Teach with SQL, not with prose

"Defining business logic as SQL expressions produces more consistent results than text instructions, because Genie applies the logic exactly as written rather than interpreting it from natural language." (Tune quality)

"Use text instructions only as a last resort when SQL expressions and examples cannot address the need." (Best practices)

  • Add tested example SQL queries, parameterized where useful, for the questions users ask most.
  • Define join relationships explicitly when keys alone aren't enough.
  • Keep text instructions short and specific. The docs note that agents "perform best with a limited, focused set of instructions".

Measure before you roll out

"Benchmarks allow you to create a set of test questions that you can run to assess Genie's overall response accuracy." (Monitor)

  • Build a benchmark set from real business questions, with two to four phrasings of each.
  • Rerun it after every change to tables, metric views or instructions.
  • After launch, review the Monitor tab and user feedback. Feedback alone doesn't change the agent's behavior; someone has to act on it.

Govern through Unity Catalog

"Row filters and column masks defined in Unity Catalog are enforced per user automatically, regardless of how the Genie Agent is shared." (Set up)

  • Users need SELECT on every object in the agent, and EXECUTE on any SQL functions used as trusted assets.

  • Entity matching is not available on tables with row filters or column masks:

    "Genie prevents you from enabling entity matching on tables with row filters or column masks." (Tune quality)

Compute and cost

  • Use a serverless SQL warehouse. A pro or serverless warehouse is required, and serverless is recommended for performance (Set up).

  • The Genie queries run on that warehouse and are billed as SQL. Genie itself is currently free for users:

    "Genie One and Genie Agents usage by users is free through January 31, 2027. Service principals are excluded from the promotion, and their usage is billed." (Genie)

Manage agents as code

Define Genie Agents in Declarative Automation Bundles so they're versioned and deployed through CI, like the rest of your platform (Best practices).

4. What this means for your setup

  • Check your MCP endpoints now. If anything still calls the old Genie MCP endpoint, move it before the end of the month:

    "The Beta endpoint, https://<workspace-hostname>/api/2.0/mcp/genie, is deprecated and reaches end of life on November 30, 2026. After that date, requests to the Beta endpoint fail." (Genie One MCP)

    Your MCP gateway calls the Conversation API, which is not affected. - Call Genie as the end user, not as a service principal. Two reasons: your BU and app row filters then apply per user, and only user usage falls under the free promotion. Service principal usage is billed. - Build the agents on your metric views. Use the semantic-layer metric views (including the bridged multi-fact ones) as the agents' data, so Genie and Tableau share one definition of each KPI. - Set up the semantic layer alongside the Data Hub pilot: a domain per business area (reusing your governed tags), Pages for the key terms, and certification on the gold tables and metric views. - If you roll Genie out in Slack or Teams, make channel replies private. Each answer runs with the asking user's permissions, but a public reply is shown to the whole channel:

    "When message visibility is public, a Genie response is visible to everyone in the channel or group DM, including members who do not have access to the underlying data." (Genie in Slack)

    With your BU and app row filters, set responses to private, or turn off Allow public messages in collaboration platforms in the workspace security settings. Pin a Genie Agent to a channel when a team should always get answers from the same agent. - For the Data Hub pilot, start with one or two focused agents (for example UA performance and subscriptions) and a benchmark set from each pilot team, then publish them in Genie One. Add agents gradually:

    "Workspaces with many Genie Agents might experience reduced routing accuracy." (Genie One chat)
