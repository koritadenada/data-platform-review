Semantic layer

Metric views: one KPI definition, every tool

Define spend, CPI, ROAS and trial conversion once. Genie, dashboards and SQL clients all read the same logic.

Genie Agents Genie One AI/BI dashboards BI tools via SQL MEASURE()

What good looks like

  • Comments on the view, every field and every measureUnits in the comment, for example "in USD"
  • display_name, format and up to 10 synonyms eachSynonyms are imported into Genie Agents automatically (YAML 1.1)
  • Composed ratios as measures, not in promptsROAS = revenue / spend, CPI = spend / installs
  • Filtered measures for common slicesSUM(x) FILTER (WHERE ...)
  • One fact table per metric view, dimensions as joinsMulti-fact: a one-to-many join or a pre-aggregated bridge view
mv_ua_performance (excerpt)
version: 1.1
source: fact_ua_campaign_daily
joins:
  - name: campaign
    source: dim_campaign
    on: source.campaign_id = campaign.campaign_id
fields:
  - name: channel
    expr: campaign.channel
    synonyms: ['network', 'media source']
measures:
  - name: roas_d7
    expr: SUM(revenue_d7_usd) / NULLIF(SUM(spend_usd), 0)
    display_name: ROAS D7
    comment: D7 cohort revenue / spend
    synonyms: ['return on ad spend', '7-day ROAS']
    format: {type: percentage}
With row filters on the sourcesMetric views still answer per user. Materialization is not available when a source has row filters, masks or ABAC policies.

  • This is where accuracy really comes from. If ROAS is defined here, Genie doesn't have to guess.
  • Point at the synonyms: "network", "media source". That's how a UA manager actually talks.
  • Multi-fact: what you built with the bridge is the documented pattern. Keep it.
  • Row filters: metric views respect them per user, but you can't materialize on filtered sources.
Genie Ontology

Domains, Pages and certification

Modeled knowledge that Genie treats as the authority.

Domains

Group assets by business area on the Discover page.

  • Built on governed tags: tag a schema, its tables join the domain
  • Subdomains up to five levels, for example Marketing/User Acquisition
  • Account-level; REST API and Terraform databricks_domain
REST API: Beta

Pages

A governed definition of one business concept, owned in a domain.

  • ROAS D7, pLTV, trial conversion, mature cohort, CAC
  • Synonyms, related assets and sources; draft, then published
  • Genie One uses the definition and cites the Page
Keep PII out of Pages: content is account-level and may be replicated globally.

Certification

System tag system.certification_status: certified or deprecated.

  • Tables, views, volumes, functions, dashboards, Genie Agents, apps, Pages
  • Certify the gold tables and metric views; deprecate the legacy report
  • Set in the UI or with SET TAG in SQL

  • Genie also learns on its own from dashboards, queries and agents, including the queries dbt runs. That's learned knowledge.
  • What we model here wins when the two disagree. That's the lever for "the number must be right".
  • Domains reuse governed tags, which you already use for ABAC. Pages are where ROAS or pLTV gets one written definition.
  • Certification is the quickest win: certify gold, deprecate the old report, and Genie One prefers the right one.
