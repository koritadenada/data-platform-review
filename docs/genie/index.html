Semantic layer

Metric views: one KPI definition, every tool

Define spend, CPI, ROAS and trial conversion once. Genie, dashboards and SQL clients all read the same logic.

Genie Agents Genie One AI/BI dashboards BI tools via SQL MEASURE()

What good looks like

  • Comments on the view, every field and every measureUnits in the comment, for example "in USD"
  • display_name, format and up to 10 synonyms eachSynonyms are imported into Genie Agents automatically (YAML 1.1)
  • Composed ratios as measures, not in promptsROAS = revenue / spend, CPI = spend / installs
  • Filtered measures for common slicesSUM(x) FILTER (WHERE ...)
  • One fact table per metric view, dimensions as joinsMulti-fact: a one-to-many join or a pre-aggregated bridge view
mv_ua_performance (excerpt)
version: 1.1
source: fact_ua_campaign_daily
joins:
  - name: campaign
    source: dim_campaign
    on: source.campaign_id = campaign.campaign_id
fields:
  - name: channel
    expr: campaign.channel
    synonyms: ['network', 'media source']
measures:
  - name: roas_d7
    expr: SUM(revenue_d7_usd) / NULLIF(SUM(spend_usd), 0)
    display_name: ROAS D7
    comment: D7 cohort revenue / spend
    synonyms: ['return on ad spend', '7-day ROAS']
    format: {type: percentage}
With row filters on the sourcesMetric views still answer per user. Materialization is not available when a source has row filters, masks or ABAC policies.

Genie Ontology

Domains, Pages and certification

Modeled knowledge that Genie treats as the authority.

Domains

Group assets by business area on the Discover page.

  • Built on governed tags: tag a schema, its tables join the domain
  • Subdomains up to five levels, for example Marketing/User Acquisition
  • Account-level; REST API and Terraform databricks_domain
REST API: Beta

Pages

A governed definition of one business concept, owned in a domain.

  • ROAS D7, pLTV, trial conversion, mature cohort, CAC
  • Synonyms, related assets and sources; draft, then published
  • Genie One uses the definition and cites the Page
Keep PII out of Pages: content is account-level and may be replicated globally.

Certification

System tag system.certification_status: certified or deprecated.

  • Tables, views, volumes, functions, dashboards, Genie Agents, apps, Pages
  • Certify the gold tables and metric views; deprecate the legacy report
  • Set in the UI or with SET TAG in SQL

Your open questions

Answers to your open questions

From your design doc, section 8.

1How does routing scale past three agents?Recommendation

Start with Genie One as the front door: it looks for a matching Genie Agent, else searches data assets. Keep agents few and well described, use domains and certification; the docs warn that many agents reduce routing accuracy. In AI assistants, add one Genie Agent MCP tool per agent when the caller knows the domain, Genie One MCP when not. Build a custom orchestrator (Agent Bricks CLI) only for custom routing; Supervisor Agent is now legacy.

Genie One routingAgent Bricks CLI
2Value matching on row-filtered tables?Recommendation

Prompt matching skips a row-filtered table entirely; a column mask only skips the masked columns. Pattern: add a small unfiltered dimension table (apps, channels, countries) to the agent with entity matching on, put synonyms in the metric views, and keep the app dictionary as example SQL or a trusted function.

Example: a user types "pixel muse", the data says PixelMuse. The fact table is row-filtered, so Genie can't learn that. Add an unfiltered dim_app (app names and aliases only, no numbers) with entity matching on: Genie maps the name, and the filtered fact table still returns only the user's own rows.

Prompt matching
3Can benchmarks run from CI through an API?Beta

Yes, in Beta. The Genie API has eval-run endpoints: genie-create-eval-run, genie-get-eval-run, genie-list-eval-results in the CLI. Benchmarks are part of the agent definition, so they deploy with it from your repo; the CI job starts a run and fails under your accuracy threshold.

CLI genie commandsAPI reference
4Genie API throughput per workspace and per user?To confirm

The current docs publish no per-workspace or per-user rate. Documented: 200,000 conversations per agent, 10,000 messages per conversation, SQL cancelled after 5 minutes, messages after 30. Use retries with exponential backoff and poll every 1 to 5 seconds. In practice the serving warehouse sets throughput. We confirm the limit for your workspace.

API best practicesTimeouts
5How is Genie billed after 31 January 2027?Documented

Genie One and Genie Agents move to the same pay-as-you-go model as Genie Code. Every identified user gets 150 DBUs free per month (about $10.50 in US East), shared across Genie One, Agents and Code; usage above that is billed in DBUs. Service principals pay for all usage, already today. Warehouse compute is billed separately. Budgets with per-user caps control spend.
